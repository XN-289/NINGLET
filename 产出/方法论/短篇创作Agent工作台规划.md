# 短篇小说创作 · Agent/Skill 交互式工作台规划

> 目标：彻底告别本地 Flask 网页 + 长篇 10+ Agent 流水线的重模式，改为**纯 Agent 对话 + Skill 嵌套**的轻量模式。你和 AI 直接对话，AI 调用一串互相串联的 Skill 完成拆解→改编→写作→质检→归档，你只检查产出并归位到文件系统。
> 适用：短篇（6k-50k 字，甜区 2-3 万），女频/男频/悬疑全题材。
> 核心原则：**素材驱动 + 网感改编 + 对话即工作台 + 文件即数据库**。

---

## 0. 为什么放弃网页模式

| 维度 | 旧模式（Flask 网页 + 长篇流水线） | 新模式（Agent + Skill） |
|---|---|---|
| 交互 | 浏览器点击、配置项、等待 | 直接对话，所见即所得 |
| 流程 | 10+ Agent 固定流水线 | Skill 按需串联，灵活组合 |
| 适用 | 10万字+长篇，设定一致性 | 短篇，单一情绪一次命中 |
| 记忆 | 复杂账本/语义检索 | 全文进上下文，无需检索 |
| 维护 | 前后端代码、依赖、部署 | 几个 .md 文件，零部署 |
| 迭代 | 改代码 | 改 prompt（即 Skill 内容） |

**结论**：短篇不需要长篇那套控制体系。把所有能力沉淀为 Skill，用对话编排，是更顺滑、更易迭代的路径。

## 1. 工作台总架构

```
你（用户）
  │  自然语言对话
  ▼
主 Agent（Codex/Claude 等对话型 Agent）
  │  按需调用、串联
  ▼
┌─────────────────────────────────────────────┐
│           Skill 层（互相连接）                │
├─────────────────────────────────────────────┤
│  ① 素材拆解    ② 选题适配    ③ 改编Brief      │
│  ④ 正文写作    ⑤ 去AI味      ⑥ 平台调性      │
│  ⑦ 归档登记    ⑧ 改编复盘    ⑨ 灵感速记      │
├─────────────────────────────────────────────┤
│           文件系统（唯一数据库）              │
│  素材库 / 改编库 / 产出库 / 登记表            │
└─────────────────────────────────────────────┘
```

**关键设计**：
- Skill 之间通过"文件约定"松耦合（A 写文件、B 读文件），不写代码胶水。
- 每次对话，主 Agent 根据你的话判断调用哪几个 Skill、什么顺序。
- 所有产出落盘到固定目录结构，文件名即索引，目录即看板。

## 3. Skill 清单（9 个，互相串联）

每个 Skill 一个目录 + 一个 `SKILL.md`，放在 `C:\Users\12112\.codex\skills\` 或项目内 `.codex/skills/`。下面给出每个 Skill 的职责、触发、输入输出、与其他 Skill 的连接。

### 3.1 `novel-source-splitter`（素材拆解）
- **职责**：把 epub/txt/pdf 小说合集拆解成"每篇一个 .md"，生成 `_拆解清单.md`。
- **触发**："拆解 XX""把这本书拆开""拆解 epub"。
- **输入**：源文件路径。
- **输出**：素材库下子目录 + 清单。
- **连接**：产出的清单供 `novel-adapter` 选题。

### 3.2 `novel-topic-matcher`（选题适配）
- **职责**：根据当下爆点话题库 + 素材清单，推荐"哪篇素材适配哪个题材标签"，给出改编优先级。
- **触发**："推荐选题""这几篇适合改什么""下周写什么"。
- **输入**：素材清单 + `灵感库/爆点话题.md`。
- **输出**：选题推荐表（原作→题材→卖点→预估难度）。
- **连接**：选定后交给 `novel-adapter` 出 brief。

### 3.3 `novel-adapter`（改编 Brief）★核心
- **职责**：输入"原作 + 目标题材"，产出 `改编brief.md`，含：原作骨架提炼、恐惧机制保留点、血肉替换清单、三幕骨架、反转点清单、开篇三行、去重自检表。
- **触发**："改编 XX 成 XX""给 XX 出个 brief""把这篇改成规则怪谈"。
- **输入**：原作 .md + 目标题材。
- **输出**：`改编库/.../改编brief.md`。
- **连接**：brief 是 `novel-writer` 的输入；写完交 `novel-deai` 去味。

### 3.4 `novel-writer`（正文写作）★核心
- **职责**：根据 brief 写正文。按目标平台调性（番茄/盐选/小红书/小程序）和字数甜区分节，每节一个反转点，情绪烈度派，去AI味实时约束。
- **触发**："写正文""按 brief 开写""写第 N 节"。
- **输入**：改编brief.md。
- **输出**：正文 .md（分节）。
- **连接**：写完交 `novel-deai` + `novel-platform-tuner`。

### 3.5 `novel-deai`（去 AI 味质检）
- **职责**：扫描正文，标红禁用词/万能情绪胶/破折号滥用/议论式对比/预告式收尾，给出逐条替换建议（情绪词后必须接具体动作/物件）。
- **触发**："去AI味""质检""过一遍WOS"。
- **输入**：正文 .md。
- **输出**：质检报告 + 修订版正文。
- **连接**：可与 writer 循环迭代。

### 3.6 `novel-platform-tuner`（平台调性校准）
- **职责**：按目标平台硬约束校准——番茄开篇300字即绝境、盐选生活化违和感、小红书图文笔记体每节800-1200字、小程序卡脖子断点付费位。
- **触发**："按番茄调一下""改成小红书体""加付费断点"。
- **输入**：正文 + 目标平台。
- **输出**：平台定制版。
- **连接**：可与 deai 合并调用。

### 3.7 `novel-archivist`（归档登记）
- **职责**：把定稿移到"可发布文章"，更新 `_改编登记表.md` 状态，生成/更新复盘。
- **触发**："归档""定稿""发布"。
- **输入**：正文定稿。
- **输出**：归档后的文件路径 + 登记表更新。
- **连接**：收尾环节。

### 3.8 `novel-retrospective`（改编复盘）
- **职责**：每篇发布后回看——原作骨架 vs 改编效果、读者反馈、可复用的"恐惧机制"，沉淀到方法论库。
- **触发**："复盘 XX""这篇效果怎么样""总结一下"。
- **输出**：`复盘.md` + 方法论补充。
- **连接**：反哺 `novel-topic-matcher` 的选题判断。

### 3.9 `novel-idea-pad`（灵感速记）
- **职责**：随手记爆点话题、素材发现、网感碎片，按周整理进 `灵感库/爆点话题.md`。
- **触发**："记一下""这个点子不错""更新爆点库"。
- **输出**：爆点话题库增量。
- **连接**：供 topic-matcher 读取。

## 4. 典型工作流（对话即编排）

### 流程 A：从素材到一篇定稿（完整闭环）
```
你：把周德东《一盒录音带》改成 AI 伴侣题材的女频细思极恐。
  → 主Agent 调 novel-adapter，读原作，产出 改编brief.md
你：brief 我看了，OK，开写。
  → 调 novel-writer 按 brief 写正文
你：去一下 AI 味，再按番茄调一下。
  → 调 novel-deai + novel-platform-tuner
你：定稿，归档。
  → 调 novel-archivist，更新登记表
你：复盘一下，把可复用的点记进方法论。
  → 调 novel-retrospective
```

### 流程 B：批量选题
```
你：下周写 3 篇，帮我从周德东里挑适合当下爆点的。
  → 调 novel-topic-matcher，读清单+爆点库，出推荐表
你：第 2、5、8 篇，出 brief。
  → 调 novel-adapter ×3
```

### 流程 C：灵感迸发
```
你：（看到个热搜）记一下：AI 换脸伴侣替换丈夫。
  → 调 novel-idea-pad，进爆点库
你：这个点子能接哪篇周德东？
  → 调 novel-topic-matcher 反查
```

### 流程 D：新素材入库
```
你：把这本《蔡骏病毒》拆了。
  → 调 novel-source-splitter
```

## 5. Skill 之间的连接约定（松耦合）

Skill 不互相直接调用，全部通过"文件约定"通信，主 Agent 做编排：

| 上游 Skill | 产出文件 | 下游 Skill 消费 |
|---|---|---|
| source-splitter | `素材库/.../_拆解清单.md` | topic-matcher |
| topic-matcher | `选题推荐表.md` | adapter |
| adapter | `改编brief.md` | writer |
| writer | `正文.md` | deai / platform-tuner |
| deai/tuner | `正文（修订）.md` | archivist |
| archivist | 更新 `可发布文章/` + `_改编登记表.md` | retrospective |
| retrospective | 更新 `方法论/` + `灵感库/` | topic-matcher（闭环） |

**好处**：任一 Skill 可独立替换/升级，不牵连其他；每步产出落盘可检查、可回溯。

## 7. 与旧体系的关系

- **保留**：旧 `WOS_*` / `WANGWEN_SKILL` / `PL_*` / `ENGINE_*` 里的**提示词内容**是宝藏，抽出来塞进新 Skill。
- **废弃**：Flask 网页（`app.py`/`static`/`templates`）、长篇 10+ Agent 固定流水线、复杂账本/语义检索——短篇用不上。
- **转型**：从"配置驱动"转"对话驱动"；从"代码维护"转"prompt 迭代"。

---

## 8. 一句话总结

> **你和 AI 对话，AI 用一串互相连接的 Skill 完成拆解→选题→改编→写作→去味→归档，产出落盘到固定目录，你只检查和对话。短篇不需要工作台软件，对话本身就是工作台。**
