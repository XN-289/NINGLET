## 为什么做

AI 写小说，快是真快，假也是真假。

"心中一凛"、"眼中闪过一丝XX"、"嘴角勾起一抹XX"、排比三连、段尾抒情总结、形容词不要钱地堆……这些是 AI 写作的指纹。读者扫一眼就知道是机器写的——不是因为写得不好，而是因为**写得太像了**。所有 AI 产出的文本都有一种共同的"正确感"，像流水线上的产品，光滑、均匀、没有毛刺。

但人写的东西不是这样的。人写的东西有偏好、有坏习惯、有突然的灵感和明显的缺陷。**好的小说不是完美的，是有个性的。**

NINGLET 的目标就是这件事：

> **用 AI 写，但写出来的东西，人看不出来是 AI 写的。**

这不是一个简单的 prompt 工程问题。它需要从**工具设计、创作流程、提示词架构、文本后处理**四个层面系统性地解决。

### 核心定位

| 维度 | 说明 |
|---|---|
| **稳定产出** | 短篇小说从构思到定稿，流水线化、可复现 |
| **人机难辨** | 反 AI 味引擎，10 维度指纹检测 + 后处理重写 |
| **短篇优先** | 6k–50k 字（甜区 2–3 万），长篇兼容 |
| **商业化就绪** | 可作为内容工厂、代写工作室、SaaS 产品底座 |

## 系统架构

NINGLET 不是一个"输入大纲、输出正文"的黑盒。它是一个**完整的创作工作台**，让作者在每一个环节都有控制权，同时让 AI 在底层做脏活累活。

```
┌─────────────────────────────────────────────────────────────────┐
│                        创作者（决策层）                           │
│  选题材 → 锁情绪 → 排反转 → 写大纲 → 逐节生成 → 去AI味 → 导出    │
└────────────────────────────┬────────────────────────────────────┘
                             │ 每一步都可以介入、修改、推翻
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│                    NINGLET 工具层                                │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐          │
│  │ 无限画布  │ │ 题材路由  │ │ 逐节配置  │ │ 右键菜单  │          │
│  │ 可视化   │ │ 字数分流  │ │ 情绪烈度  │ │ 20+操作   │          │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘          │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐          │
│  │ 记忆系统  │ │ 一致性检查 │ │ AI味检测  │ │ 导出系统  │          │
│  │ 分层检索  │ │ 五维度   │ │ 10项打分  │ │ 多格式   │          │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘          │
└────────────────────────────┬────────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│                   反 AI 味引擎（核心）                            │
│  禁用词过滤 → 结构规则约束 → 对话规则 → 情绪规则 → 后处理重写     │
└────────────────────────────┬────────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│                   大模型 API 层                                  │
│  DeepSeek / 通义千问 / 豆包 / GPT（任意 OpenAI 兼容接口）         │
└─────────────────────────────────────────────────────────────────┘
```

关键设计原则：

- **作者永远是决策者**。AI 是工具，不是作者。每一个生成结果都可以被修改、重写、推翻。
- **控制颗粒度要细**。不是"写一篇"，而是"这一节用这几个角色、这个节奏、这种情绪、这个场景类型"。
- **反馈回路要短**。写完立刻检测、发现问题立刻重写、不用导出到别的工具。

## 反 AI 味引擎

这是 NINGLET 的核心。不是调一个 prompt 就完事——是一整套从生成到后处理的流水线。

### AI 味从哪来？

AI 写作有 10 个维度的"指纹"：

| 维度 | 典型症状 |
|---|---|
| 禁用词 | "心中一凛""眼中闪过一丝""嘴角勾起一抹" |
| 句式 | 排比三连、段尾抒情总结、对仗工整 |
| 形容词 | 堆砌、空洞、不落地 |
| 节奏 | 均匀推进，无快慢张弛 |
| 情绪 | 隔靴搔痒，不敢写烈情绪 |
| 对话 | 每句都完整、都文明、都有信息量 |
| 细节 | 场景描写像布景，不像有人住过 |
| 转折 | "然而""但是"机械过渡 |
| 结尾 | 升华总结，强行正能量 |
| 结构 | 三段式骨架外露 |

### 两个流派

- **情绪烈度派**（短篇用）：直白烈情绪，情绪词后必须接一个此刻场景里特有的具体动作/物件。
- **克制留白派**（长篇用）：Show Don't Tell，靠动作和细节暗示。

短篇必须用情绪烈度派——这是和通用 AI 写作工具最大的审美冲突点。

## 创作流程

短篇流水线极简为 3 段：

```
构思 → 写 → 去AI味
 │     │     │
 │     │     └─ 禁用词扫描 + 结构检查 + 后处理重写
 │     └─ 注入风格硬约束 + 题材模板 + 短篇格式
 └─ 锁情绪 + 选题材三幕 + 排反转点
```

### 字数路由

| 字数 | 模式 | 说明 |
|---|---|---|
| < 6k | 单篇流式 | 一次生成全文 |
| 6k–12k | 单篇流式 | 甜区下沿，一次生成 |
| 12k–50k | 多节预规划 | 全部节拍先规划，再逐节写 |
| > 50k | 长篇管道 | 切换到长篇模式（rolling window） |

### 支持题材

- **恐怖悬疑**：规则怪谈 / 民俗 / 无限流 / 细思极恐
- **女频**：甜宠 / 虐恋 / 追妻火葬场 / 重生复仇
- **男频**：系统流 / 重生 / 扮猪吃虎
- **治愈**：日常 / 共鸣 / 情感
- **脑洞**：玩梗 / 反转 / 社会热点

## 快速开始

### 环境要求

- Python 3.8+
- 任意 OpenAI 兼容大模型 API（DeepSeek / 通义千问 / 豆包 / GPT 均可）

### 安装

```bash
git clone git@github.com:XN-289/NINGLET.git
cd NINGLET
pip install -r requirements.txt
```

### 配置

```bash
cp .env.example .env
# 编辑 .env，填入你的 API Key
```

`.env` 示例：

```env
PRIMARY_API_KEY=sk-your-key-here
PRIMARY_API_ENDPOINT=https://api.deepseek.com/v1/chat/completions
PRIMARY_MODEL=deepseek-chat
PORT=20010
HOST=127.0.0.1
```

### 启动

**Windows：** 双击 `start-short.bat`

**命令行：**

```bash
python app.py
```

启动后浏览器访问 `http://localhost:20010`。

```

├── app.py                    # Flask 后端（8 个核心路由）
├── modules/
│   ├── shortstory.py         # 短篇引擎：字数路由 + 题材库 + 提示词

├── static/                   # 前端：无限画布 + 右键菜单
├── templates/                # 页面模板
├── docs/
│   └── research/             # 写作方法论调研文档
└── 产出/                     # 创作产出（见下）
```

### 产出目录说明

`产出/` 下按类型组织，**真实内容已脱敏**，仅保留结构占位：

| 目录 | 用途 | 公开状态 |
|---|---|---|
| `方法论/` | 写作技法、创作准则 | ✅ 公开（通用方法论） |
| `拆解文章/` | 优秀作品骨架拆解 | 🔒 占位（版权敏感） |

| `改编库/` | 改编作品 + brief | 🔒 占位（商业产出） |
| `灵感库/` | 爆点话题库 | 🔒 占位（商业资产） |
| `素材库/` | 改编素材索引 | 🔒 占位（商业资产） |

## 商业化路径

NINGLET 的设计天然支持商业化拓展：

- **内容工厂**：稳定批量产出短篇，对接番茄/七猫/小红书等平台
- **代写工作室**：人工把控创意，AI 跑量产出，人机协作提效
- **SaaS 产品**：包装为在线短篇创作工具，订阅制
- **IP 孵化**：短篇作为网文/短剧/有声书的内容源头
